- New product repository initialized on build/living-canvas in a separate living-canvas directory; there is no existing product branch or user code to isolate with another worktree.
- Parallel workers have disjoint ownership defined in docs/INTEGRATION.md; protocol and cross-process integration remain root-owned.

- Hardware/model-dependent voice performance must be measured. Missing native toolchains may be resolved using official prebuilt Windows binaries or maintained N-API bindings rather than requiring a local compiler.

## Current implementation
- Desktop foundation: Electron/React/TypeScript app, typed preload, restricted IPC, source build and runnable Windows directory package.
- Account/provider: fresh official browser sign-in with PKCE/state/nonce/JWT verification, OS-protected credentials, refresh/revocation, model discovery, completed-stream checks, namespaced strict teaching tools, bounded repair and quota/error recovery.
- Local lessons: SQLite snapshots/events, semantic edit revisions, local history/export/delete, prepared teaching metadata separated from actual presentation checkpoints.
- Canvas: editable semantic 2D entities, hand-style primitives, equations, progressive reveal, selection/pointing, pan/zoom, notes, keyboard access, and dynamically generated experiment controls.
- Generated computation: QuickJS WASM in a terminable worker in a separate sandboxed renderer, resource/output limits, preflight execution, external watchdog, seeded replay with tick-indexed input history.
- Teacher: general-topic prompt and validated teaching steps, bounded visual/conversation context, sequential presentation, cancellation epochs, actual visible/heard progress acknowledgements, preservation of learner edits. Content is generated by the connected account.
- Voice: local Kokoro af_heart female synthesis in a resident, cancelable native worker, female-preferred Windows fallback, pinned whisper.cpp English recognition, bounded rolling transcription with voice-activity/silence detection, automatic follow-up submission, audio-clock word display, and completed-chunk narration checkpoints.
- Model/depth correction: exact selected model preservation with no silent substitution, requested/served model metadata per provider round, and automatic substantive lesson continuation after actual presentation until a useful question or completion.
- Graphify: local code-only extraction and traversal used on this implementation; dependencies, builds, models, and private runtime data excluded.

## Remaining acceptance work
- The user completed fresh ChatGPT authorization. The historical chosen model is gpt-6-astra; old responses lack served-model metadata. New live verification is recorded in validation.md and must not be inferred from fixture responses.
- English recognition and neural female weights have been installed for the authorized local upgrade. Physical microphone accuracy, speaker echo, and playback latency still need device trials. Default speaker mode gates recognition during playback; headphone mode allows spoken interruption without claiming acoustic echo cancellation.
- Silero VAD, precise word-level forced alignment, freehand sketch interpretation, learner evidence across separate lessons, 3D, and broad educational/numerical validation remain beyond this build.
- Saved replay has explicit time/history limits and a reset recovery path. Acceptance of a generated model means it ran within the boundary, not that its scientific claims were independently established.
- Final integrated verification results are recorded in validation.md. The 16-task plan is not marked fully complete while live/device acceptance and the listed planned capabilities remain unverified or unimplemented.
