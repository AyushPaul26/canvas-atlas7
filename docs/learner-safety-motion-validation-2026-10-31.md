# Canvas Atlas 0.5.0 — safety, animation and resilient notes

## Result

The lesson footer includes **Animate this** and **Create notes offline**. Animation requests reuse the current concept and teaching pipeline. Curved path cues follow the same audio clock as reveals/tweens, and existing Pause/Resume/Replay controls remain authoritative. Offline notes copy actually presented explanation prefixes and selected diagrams into a labelled, colourful study record without model, key, catalog or quota access. They do not claim to add AI analysis or invented revision content.

The screenshot's original ChatGPT error occurred before PDF creation. There was no retained HTTP diagnostic from that request, and no live inference was authorized for testing. Therefore its exact remote cause is **not established**. A synthetic real-adapter regression verifies the existing supported Responses envelope. Failed HTTP/stream responses now expose only allowlisted status, code and parameter details, with bounded body size/deadline and no raw response prose. There is no automatic retry, paid repair or provider fallback for notes. Offline notes provide a working route independent of that remote failure.

## Safety boundaries

- New learner topics/questions/needs are checked before persistence and model readiness. Denied input causes no inference or stored learner evidence/message.
- Common provider instructions apply to ChatGPT, Gemini and Groq. Entire buffered responses, tool arguments, native history and structured refusals are checked before accepting content. Safety rejection is terminal and bypasses paid repair budgets.
- Rechecks cover saved/replayed lessons, branch checkpoints, linked course sessions, cached course summaries, notes publication/open/export, source extraction and narration. Existing rejected data is withheld, not automatically deleted; unsuitable legacy lesson summaries retain only neutral labels and the ID required for deletion.
- Dynamic simulation inputs/results, labels, measurement keys/values and errors are checked before display. Rejected frames reset the worker and carry fixed public copy. Runtime preflight converts safety failures to a typed terminal error, preventing repair or provider-history publication.
- Imported unsuitable material is rejected before promotion; its new staging data is cleaned. Public PDF source previews show checked extracted text, not unreviewed embedded images. Internal bounded raster tooling is retained but not exposed through the learner preview bridge.
- A safety refusal stops queued presentation, voice input/output, automatic progression and simulations. The draft remains editable; recovery offers Edit question or New topic without automatically resending.

## Limits

These are **basic guardrails**, combining local English and selected Hindi/Hinglish rules with provider instructions. The checks normalize an inspection copy (including selected Unicode/escape obfuscations), inspect JSON/tool text and reject oversized inspection input. They preserve the original safe Unicode content.

They do not establish universal semantic safety across languages, encoding tricks or unlabelled geometric drawings. No semantic/image moderation service or extra paid moderation request was added. Clinical anatomy, reproduction, puberty, consent, non-graphic history and legitimate technical/defensive cybersecurity study have positive allow-case tests; they are not categorically banned by an anatomy or violence keyword list. Educational framing cannot exempt an explicitly disallowed request.

Live teaching quality, every model's animation choices and acceptance of the previously rejected ChatGPT request have not been measured with real credentials. Cancelling an already dispatched provider request cannot guarantee the provider will not charge for work already performed.
