Home → Start → exact question “What would you like to learn today?” → unrestricted topic → Create roadmap → generated concepts and objectives → Start Teaching. Creating a roadmap does not request teaching or fabricate a learner message. An unconnected learner may enter a topic and open Settings to connect ChatGPT, Gemini, or Groq before requesting a roadmap. An unavailable saved model opens Settings without losing the topic. Browser preview explicitly announces its limitations and supplies no tutoring or authentication.

Upload Study Material opens the native PDF/TXT/Markdown picker and extracts locally. The UI reports actual page progress, supports cancellation, and previews readability coverage and warnings. Empty extraction blocks course planning and explains the text-based export alternative. Create course outline uses only ready/partial readable documents. Open lesson first shows that lesson's roadmap; Start Teaching remains explicit. Saved courses load from the desktop bridge. Source references open only validated saved previews through getSourcePreview; physical page references may show the document's printed page label. No external file URLs are rendered.

Session history contains only stored sessions. At most 8 recent sessions appear in the sidebar, with a full scrollable list in History. Lists are local and render all returned sessions; no search or URL-persisted sensitive learning text. Topic drafts and question drafts remain in memory. No secrets are persisted by the renderer.

Buttons prevent duplicate async operations. Errors retain entered text and scene, identify the failed action, and allow retry. Scene edits autosave after 600ms; Save gives explicit acknowledgement. Navigation saves dirty scenes before changing lessons. Failures keep the learner in place. Export saves the current simulation checkpoint first, then delegates to the desktop save dialog. OS close uses a closing/readyToClose handshake to flush presentation progress and save before the window closes; duplicate closing events are ignored. Deletion uses an app-owned modal, names the lesson and loss, focuses Cancel first, closes only on successful deletion, and updates history. Sign-out does not delete local lessons.

Tutor status and transcript derive from real bridge events. Superseded epochs and other sessions are ignored; import progress is handled outside session filtering. Ordinary Pause suspends teaching audio and simulation without cancelling its accepted request. Questions, canvas edits, model changes, navigation and close interrupt playback, save its checkpoint, then interrupt generation. Learner questions and the three teaching adjustments remain available when the transcript is collapsed. Simulation source runs only through the sandbox bridge; the UI renders its validated returned primitives. Changing a control pauses audio and applies the validated value. Resume after a manual change requests a short explanation using current values. Narration uses local synthesis or explicitly selected ElevenLabs account voices. Microphone recognition stays local; the renderer never makes provider requests. Voice/provider/key changes pause teaching and cancel stale synthesis; preview cannot acknowledge lesson progress. Keys are OS-encrypted and omitted from public configuration and lesson exports.

Canvas dragging has keyboard alternatives: select the accessible scene item, use arrow keys to move (Shift for 10px), edit text in the inspector, and Delete to remove. Toolbar pan mode, zoom buttons and Fit remain available without pointer gestures. Native dialogs provide focus containment, Escape and focus restoration. Every form uses noValidate and associated labels; Enter submission is IME-safe. Focus indicators, reduced motion and responsive narrow layouts are required. English locale uses the device timezone for local session dates.


Continuous voice: local VAD opens one microphone session, updates visible drafts, and finalizes after silence. Questions auto-send after a 650ms Cancel & edit window; initial topic confirmation remains explicit so recognition errors can be corrected. Microphone input remains enabled across tutor turns but speaker playback gates recognition by default. Headphones mode is an explicit opt-in to spoken interruption; Interrupt & speak is always available while voice is active. Leaving/closing releases capture. Word display uses approximate audio-duration pacing, while persistence records completed spoken chunks. TTS prefetch is limited to one next segment.

Teaching uses useLessonPlayback with actual audio frames and a visual readiness barrier. Unavailable or failed audio leaves an actionable retry state and never becomes heard progress through timed text. Completed chunks and visual cues are saved before the full presentation acknowledgement; only that acknowledgement can cover a concept. The two-beat queue drains before a permitted continuation, including a finished concept with remaining roadmap concepts. Review replay uses immutable accepted content and its baseline, does not write playback/progress, duplicate messages, or auto-continue. Saved incomplete playback resumes acknowledged chunks and restarts the incomplete chunk explicitly. Learner notes remain visually separate from the accepted teacher baseline. Understanding checks offer distinct answer, help-requested, and skipped evidence; coverage is not mastery. Revisit retains previously covered concepts.

Follow-up questions retain a branch return point. When the answer finishes, Back to lesson restores the accepted interrupted teaching step through the same checkpoint resume path. Follow-up listening does not cover the interrupted concept. Local speaking speed is an explicit bounded preference (0.75–1.25×) applied to the next spoken chunk; it does not promise emotional voice control or forced alignment.

The backend's restored playback mode is authoritative. A fully acknowledged branch returns as review, replays its accepted chunks, and writes no new presentation evidence or continuation. Restoring a checkpoint without a simulation clears a follow-up experiment even when the original canvas operation was append/update. A checkpoint with an inherited simulation restores that exact saved experiment; new append/update teaching keeps its current accepted simulation.

Requested and served model names come from recorded metadata, and unknown service metadata is labelled unknown. A saved unavailable model blocks teaching until a valid selection is made.

Teaching connection details live in Settings. The persistent “ChatGPT connected” wording is absent from the header and sidebar; account/settings actions, account identity, indicators, and requested/served model evidence remain. The separate official-sign-in success notice remains. Connecting or replacing a valid Gemini/Groq key automatically activates that service without another provider-switch step. The last active provider and exact per-provider model selections survive restart. A remembered unavailable model requires explicit recovery; failures never trigger a silent provider/model fallback.

Active provider/model/key changes pause/checkpoint teaching and invalidate obsolete work while keeping committed beats locally resumable. Merely typing, refreshing an unchanged catalog, or removing an inactive key does not interrupt narration or continuation. API teaching works with ChatGPT disconnected. Narration selection remains independent of the teaching service. Material citations, simulations, and presentation acknowledgements retain the same validation rules under every provider.

On desktop, playback and the main question form occupy a reserved footer. The lesson body scrolls independently; understanding checks and the optional transcript share a separate scrolling side rail. The check does not displace the drawing. Native spatial views may require body scrolling to reach the companion diagram, while Pause and questions remain reachable. Graphics fallback keeps both masses and the equation visible above the footer and clear of the canvas toolbar at compact and large desktop sizes.

Generate notes is a footer action available after any nonempty acknowledged tutor explanation, without completing the roadmap. It discloses use of the selected AI service and pauses/interrupts teaching, saves edits and reloads persisted progress before one explicit generation request. No automatic generation or retry occurs. Cancel, leaving the lesson and teaching-connection changes invalidate pending UI results. Failure retains the prior saved PDF and offers another explicit generation. Open PDF and Save PDF read the saved artifact offline, require no teaching connection and never regenerate; Save PDF uses the native Save As dialog. Pending, success and actionable error feedback stay beside the notes action, with keyboard-accessible controls and the existing footer scroll ownership.

Create notes offline is a separate explicit footer action after studying. It uses saved explanations and diagrams on this device, requires no teaching connection and sends no AI request. Its own progress label identifies an offline study record; the Generate notes button does not show AI generation while the local record is being prepared. Saved local records remain labeled as offline after restart. There is no automatic switch between AI notes and offline records.

Animate this requests meaningful movement for the current concept through the existing selected teaching service. Diagrams use bounded declarative paths, numeric changes and staged reveals; adjustable simulations are offered when they help explain the idea. The current lesson, selected drawings, interruption/checkpoint behavior and narration controls remain authoritative. Pause freezes the accepted audio-driven visual pose, Resume continues it, Replay reproduces it, and reduced motion uses explanatory endpoint poses. This action adds no quiz flow or decorative ambient animation.

A recognized safety stop clears queued teaching, interrupts audio and simulation, pauses the lesson and shows neutral learning guidance. The current draft and visible diagram remain available. Edit question focuses the existing draft; New topic opens the topic form. Neither recovery action resubmits a blocked request automatically, and stale beats from the stopped epoch are ignored.

Original topic admission completes in the backend before session creation or roadmap/progress UI. Uncertain intent requests clarification; unavailable classification leaves the draft intact. Suggestions only prefill the question. Settings disclose provider quota use. Unknown saved titles use a neutral review placeholder until approved; signed approved work remains accessible offline. Provider/topic/navigation changes cancel stale admission. New-topic recovery remains silent until the learner submits. Notes previews and exports use an exact verified PDF byte snapshot.

Explorable model behavior follows the approved visual-refinement spec in docs/superpowers/specs/2026-10-31-visual-refinement.md. SimulationArtifact.engine model selects bounded versioned JSON maths/mechanics; old programs retain QuickJS behavior. Worker dispatch, controls, history and canonical SceneEntity frames remain the shared source of truth. The numeric JSXGraph view never executes model-provided expressions or advances time independently. Entering Explore graph awaits pause/settle; a released two-axis drag creates one committed input. Resuming teaching returns to Diagram. Numeric controls remain keyboard alternatives, and graph failures retain the canonical board. Save/reopen and notes use existing persistence and presented-diagram paths.

The Visual view button group is owned by visuals/MathExplorer, with native button keyboard behavior and aria-pressed selection (not tabs). The 3D camera group is owned by visuals/Scene3D; it accepts pointer, arrow-key, zoom and Reset actions only while teaching is stopped/paused. Camera exploration is local display state; resumed/new accepted views restore the teaching camera. 2D fallback and presentation receipts stay owned by VisualStage. Both viewers use existing Button/Notice/scroll/token owners and have no new billing or network operation.
